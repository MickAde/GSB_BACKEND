AI Study Buddy Platform
Detailed Product Requirements Document (PRD) For Development
Project Overview
The platform is a cloud based AI powered educational ecosystem for schools.
The platform will have five major user roles:
1.Students
2.Teachers
3.Main Admins
4.Sub Admins
5.Optional Parent Access
The platform is primarily web based for the first version.
The platform must be responsive across:
desktop
tablet
mobile browser
The system should use role based authentication and multi tenant architecture.
Each school operates independently inside the same platform.
One school must NEVER access another school’s data.

PLATFORM ENTRY FLOW AND USER NAVIGATION
HOME PAGE FLOW
When users open the platform, the homepage should present two primary entry options:
1.Enter as Visitor
2.Enter Through School
This structure is very important and should guide the entire authentication architecture.

VISITOR FLOW
If user selects:
Enter as Visitor
Flow should be:
1.Visitor Registration Page
2.Email Verification
3.Visitor Dashboard Access
Visitor requirements:
registration requires email
email verification mandatory
one week free trial access
limited feature access only
subscription required after free trial expires
Visitor role is a FULL platform role and must be treated separately from school users.
Visitor users are independent users and are not attached to any school.

SCHOOL FLOW
If user selects:
Enter Through School
Flow should be:
1.School Selection Page
2.Role Selection Page
3.Login Page
4.Dashboard Access

SCHOOL SELECTION PAGE
The school selection page should include:
search bar for schools
grid/list view of onboarded schools
school logo support
clickable school cards
Only schools onboarded manually by platform owners should appear.
Schools are NOT self onboarding.
Platform owners manually onboard schools into the system.

ROLE SELECTION PAGE
After school selection, users should see:
Proceed As:
Student
Teacher
Admin
System then routes users to the appropriate login system.

STUDENT LOGIN FLOW
Students should NOT use emails.
Student login should use:
student username/admission number/student ID
password
Platform owners initially generate credentials based on information submitted by the school.
Students can later:
change password
reset password through approved recovery methods

TEACHER LOGIN FLOW
Teachers should use:
email
password
Teachers can:
change password
reset password

ADMIN LOGIN FLOW
Admins should use:
email
password
Admin system determines:
Main Admin
OR
Sub Admin
based on permissions assigned in backend.

USER ROLE STRUCTURE
The platform contains the following user roles:
1.Visitor
2.Student
3.Teacher
4.Main Admin
5.Sub Admin
6.Optional Parent Access

GENERAL SYSTEM REQUIREMENTS
Authentication System
Authentication must follow the exact platform entry flow defined above.
School accounts are NOT publicly self created.
Platform owners manually onboard schools.
During onboarding:
school data is uploaded
student accounts are generated
teacher accounts are generated
admin accounts are generated
Credential structure:
Students:
username/admission number/student ID
password only
no email required
Teachers:
email
password
Admins:
email
password
Visitors:
email authentication mandatory
one week free access before subscription
MULTI TENANT SYSTEM REQUIREMENT
The platform must support multiple schools.
Each school must have:
separate database scope
separate students
separate teachers
separate admins
separate reports
separate analytics
No school should see another school’s information.

OCR TRANSCRIPTION SYSTEM
Handwritten notes should:
convert to editable text
preserve original meaning
avoid AI interpretation during transcription
IMPORTANT:
The transcription section should ONLY contain raw extracted text.
No summaries should appear inside transcription.

TRANSCRIPTION REVIEW SCREEN
After OCR:
show editable text
provide audio read aloud button
allow students correct errors
allow save changes
allow cancel
allow final confirmation
Only after confirmation should AI proceed to summary generation.

AI SUMMARY SYSTEM
After confirmation:
AI generates:
1.One paragraph summary
2.Bullet point summary
3.Key learning points
Original notes must remain accessible separately.
